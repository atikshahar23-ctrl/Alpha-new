# Lyrics Translator — מדריך פרסום ל-Google Play

## ⚠️ קרא קודם: שלושה מכשולים אמיתיים

לפני שממשיכים לשלבים הטכניים — שלוש נקודות שיכולות לגרום לדחיית האפליקציה
או להסרתה, ומה עשינו/צריך לעשות לגביהן:

### 1. זכויות יוצרים על מילות השירים — הסיכון האמיתי ביותר
LRCLIB ו-lyrics.ovh הם מאגרים **קהילתיים/חינמיים, לא בעלי רישיון רשמי**
(בשונה מ-Musixmatch או Genius, שמשלמים לחברות התקליטים על הזכויות).
הצגת מילות שירים בלי רישיון היא, טכנית, הפרת זכויות יוצרים — והחשיפה
המשפטית **גדלה משמעותית** אם המוצר גובה כסף. אפל ידועה בייחוד כמחמירה
בנושא הזה; גוגל פחות אגרסיבית בבדיקה הראשונית אך עדיין תסיר אפליקציה
בעקבות תלונת DMCA מבעל זכויות.
**אין דרך "לתקן" את זה טכנית** — זו החלטה עסקית/משפטית. ההמלצה
(מפורטת למטה) היא להתחיל בגרסה חינמית לגמרי, ולשקול רישיון רשמי
(Musixmatch API בתשלום, למשל) רק אם/כשעוברים למודל בתשלום.

### 2. אסור להשתמש בשם/מותג של Spotify
תנאי המפתחים ומדריך המותג של ספוטיפיי אוסרים שימוש בשם או בלוגו שלהם
בתור חלק מהמותג שלכם (למשל אסור לקרוא לאפליקציה "Spotify Translator").
**כבר עשינו את זה נכון**: האפליקציה נקראת "Lyrics Translator", האייקון
הוא סימן גלים גנרי (לא הלוגו של ספוטיפיי), ותיאור החנות מנוסח כ"מסתנכרן
עם אפליקציות מוזיקה מובילות" ולא "אפליקציית Spotify". מותר לציין
"אינטגרציה עם Spotify" כעובדה בגוף התיאור (כפי שאלפי אפליקציות צד-שלישי
עושות) — רק לא בשם/בלוגו/במשתמע כאילו ספוטיפיי עצמם יצרו את זה.

### 3. זיהוי מה מתנגן ברקע — אנדרואיד מול iOS
**חדשות טובות: האפליקציה כבר בנויה נכון לזה.** היא לא "מאזינה" להתראות
המערכת (NotificationListenerService) — במקום זה היא שואלת ישירות את
ה-Spotify Web API הרשמי "מה מתנגן עכשיו?", בהרשאת המשתמש (OAuth). זו
בדיוק השיטה הרשמית שספוטיפיי מספקים, והיא עובדת **זהה** באנדרואיד וב-iOS
— אין הבדל פלטפורמה בנקודה הזו, כי לא תלויים בהרשאות מערכת ספציפיות.

ההסתייגות האמיתית (טכנית, לא עקרונית): כשהאפליקציה **ברקע** (המשתמש
עבר לאפליקציה אחרת), מערכת ההפעלה עשויה להאט/להשהות את בדיקת ה"מה
מתנגן" התקופתית כדי לחסוך סוללה — זה משפיע על כל אפליקציית PWA/TWA
בשתי הפלטפורמות, לא רק על זו. כשחוזרים לאפליקציה היא מתעדכנת מיד.

## 💡 האסטרטגיה המומלצת (משלבת את כל הנקודות למעלה)

**שלב 1 — השקה חינמית לגמרי (הגרסה שהוכנה כאן):**
בלי מנוי, בלי רכישות. בודקים שהחנות מאשרת בלי בעיה, אוספים משוב אמיתי,
ורואים אם עולה בעיית זכויות יוצרים בפועל — לפני שיש כסף על הכף.

**שלב 2 — ערך מוסף ייחודי (בעתיד, לא בגרסה הזו):**
להזיז את המיצוב מ"אנחנו מציגים מילים בחינם" (מסוכן משפטית) ל**"אפליקציית
לימוד שפה דרך מוזיקה"** (הרבה יותר מוגן ומקובל בחנויות) — למשל: לחיצה על
מילה בשיר לתרגום מדויק + הגייה, כרטיסיות זיכרון (flashcards) ממילים
משירים אהובים. אפליקציות בקטגוריה הזו מקבלות אישור בקלות רבה יותר.

**שלב 3 — מנוי בתשלום נמוך (רק אחרי שלב 2):**
מחיר נגיש (5-10 ש"ח לחודש, בהתחשב שספוטיפיי עצמו כבר עולה ~21-30 ש"ח),
או מודל צפייה בפרסומת לפתיחת גישה זמנית — לא לפני ששלבים 1-2 הוכיחו
שהאפליקציה עוברת בדיקה נקייה ושיש לה בסיס משתמשים אמיתי.

**זה לא מומש בקוד עדיין** — הגרסה הנוכחית היא שלב 1 (חינמית). שלבים 2-3
הם החלטת המשך, לא חלק מהמסירה הזו.

## מה נשאר לך לעשות (מנהלתי — רק אתה יכול)

### שלב א' — אחסון (חינמי, ~5 דקות)
האפליקציה חייבת לרוץ בכתובת HTTPS אמיתית לפני שאפשר לארוז אותה ל-TWA.
האפשרות הכי פשוטה בלי לגעת בקוד:
1. היכנס ל-[Netlify Drop](https://app.netlify.com/drop)
2. גרור לשם את תיקיית `dist/` (אחרי `npm install && npm run build` בתיקייה הזו)
3. תקבל כתובת קבועה כמו `https://lyrics-translator-xyz.netlify.app`

(חלופה: repo חדש ב-GitHub + הפעלת GitHub Pages — פחות מיידי אך גם חינמי וקבוע יותר.)

### שלב ב' — אימות שה-PWA תקין
פתח את הכתובת מ-Chrome בנייד או שולחני, לחץ F12 → Lighthouse → הרץ בדיקת
PWA. אמור לקבל ציון "Installable" מלא (כל הרכיבים כבר מוכנים לזה).

### שלב ג' — אריזה לאפליקציית אנדרואיד (TWA)
1. היכנס ל-[PWABuilder.com](https://www.pwabuilder.com) (כלי חינמי של מיקרוסופט)
2. הדבק את הכתובת מ-Netlify, לחץ "Start"
3. בחר "Android" → "Google Play"
4. הכלי ייצור עבורך **מפתח חתימה (signing key) ו-Android App Bundle (.aab)** מוכן להעלאה — שמור את קובץ המפתח במקום בטוח, תצטרך אותו לכל עדכון עתידי

### שלב ד' — חשבון Google Play Console
1. הירשם ב-[play.google.com/console](https://play.google.com/console) (עלות חד-פעמית: 25$)
2. צור אפליקציה חדשה, מלא את פרטי ה-Store Listing (יש טיוטה מוכנה ב-`STORE-LISTING.md`)
3. העלה את קובץ ה-PRIVACY.md כעמוד פרטיות מקוון (אפשר לארח ב-Netlify גם כן, כדף נפרד) והדבק את הקישור בשדה "Privacy Policy URL"
4. העלה את קובץ ה-.aab מ-PWABuilder
5. מלא את שאלון "App Content" (דירוג תוכן, קהל יעד, הצהרות — ראו את
   ההערות ב-`STORE-LISTING.md` תחת "הערות לבדיקת Google")
6. שלח לבדיקה — משך בדיקה טיפוסי: מספר שעות עד מספר ימים

לאחסון → אם רק תוכן האתר השתנה (לא מבנה ה-manifest/permissions), אין
צורך לבנות .aab חדש — TWA טוען את התוכן החי מהאתר בכל פתיחה.
